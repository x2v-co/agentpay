AgentPay

Permission. Procurement. Proof.

An agent purchases its next inference inside an owner's spending policy, then recovers its result and verifies settlement on Monad.

The owner is part of the loop.

Recorded browser interaction. The coding task is a scripted, locally executable fixture. The model usage and Monad payment are separate historical evidence. No new model call or payment is made in this video.

One request across three trust boundaries.

01 / OWNER + AGENT

Define the permission

Policy + checkpoint

The owner bounds wallet, merchant, model, chain, asset, expiry and budget. Discovery joins aiplans.dev data with Toolkit machine offers. Human checkout is ineligible.

02 / SDK + MERCHANT

Buy the inference

Reservation + x402 + Permit2

A purchase binds the request digest and token bounds. The merchant records provider output and usage before settlement. Retries must preserve the purchase ID.

03 / MONAD + RESULT

Verify the settlement

Transfer + receipt + recovery

Validate the expected payer, payee, asset and amount. Unknown settlement stays pending. The agent can reconcile or recover purchase-scoped access to its result.

Task checkpoint → discovery → bounded authorization → metered settlement → result recovery → resume

AgentPay adds the procurement policy, request binding and recovery lifecycle. x402 and Permit2 remain the payment standards. Monad supplies EVM-compatible testnet settlement; this demo claims no measured speed or cost advantage over other chains.
